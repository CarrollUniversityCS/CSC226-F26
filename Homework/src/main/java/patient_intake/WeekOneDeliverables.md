## Getting Started

### Directory Structure & Java Package Conventions

In Java, modern IDEs like Visual Studio Code are particular about *where* Java code is placed. This is due to Java's package system and build tools that expect a standardized directory layout. Following these conventions ensures your IDE can properly recognize, compile, and run your code.

#### Current Project Structure

This project follows **Maven's Standard Directory Layout**—the conventional folder structure that virtually every Maven project uses. Following this convention (rather than inventing your own) is exactly what "convention over configuration" means: Maven already knows where to look for your source code, your tests, and your build output, so you don't have to configure any of it yourself.

```
HospitalSimulator/
├── HospitalSimulator_Roadmap.md         # Semester-wide project overview and weekly breakdown
├── pom.xml                              # Maven build configuration (dependencies, build settings)
├── src/
│   ├── main/
│   │   └── java/
│   │       └── patient_intake/          # Week 1 package
│   │           ├── Main.java               # Entry point for the simulation
│   │           ├── Patient.java            # Patient data class
│   │           ├── PatientRegistry.java    # Array-based patient storage
│   │           ├── patients.csv            # Sample patient data file
│   │           ├── WeekOneDeliverables.md  # Week 1 specific instructions
│   │           └── todo.md                 # Week 1 task checklist
│   └── test/
│       └── java/
│           └── patient_intake/          # Week 1 test package
│               ├── PatientTest.java           # Unit tests for Patient class
│               └── PatientRegistryTest.java   # Unit tests for PatientRegistry class
├── target/                              # Build output (generated by Maven)
└── .vscode/
    └── settings.json                    # VS Code Java project settings

```

#### Understanding the Package Structure

1. **`src/main/java/`** - Maven's standard location for all production (non-test) Java source code. Every Maven project expects application code to live here—this is not specific to our project, it's the convention across the entire Java ecosystem.
2. **`src/test/java/`** - Maven's standard location for test code. Keeping tests in a separate tree from `src/main/java` (rather than mixed in alongside your source files) means Maven can compile and run them separately, and your test code is never accidentally bundled into a shipped `.jar`.
3. **`patient_intake/`** - This directory, nested under `src/main/java/` (or `src/test/java/` for tests), serves as both:
   - A **package** for organizing related Java classes (`package patient_intake;`)
   - A **module folder** containing all Week 1 deliverables
4. **`target/`** - This is an automatically generated and filled directory as a result of running and compiling the code via Maven
5. **`.vscode`** - This tells VS Code where the classpath root directories are (`src/main/java` and `src/test/java`); if you are using Eclipse, this can be ignored.

> **Why does this matter?** Because we now follow Maven's standard layout, our `pom.xml` no longer needs to tell Maven where to find source or test code—it just works out of the box. This also means any Maven-aware tool (IDEs, CI pipelines, other developers) will immediately understand this project's structure without reading any documentation.

### Understanding Maven

Apache Maven is a build automation and project management tool. Maven helps developers stanarize how projects are structured, automatically installs requirements, and automates repetiative tasks like compiling, testing, and ultimatly packaging code. 

Instead of triggering build scripts, we use the `convention over configuration` principle. The **Standard Directory Layout** (`src/main/java` for source code, `src/test/java` for tests) is the clearest example of this in action—by placing our files where Maven expects them, we avoid having to spell out custom source paths in `pom.xml` at all.

We will learn more about Maven over the course of the semester, but for now, it's best understood that Maven is essentially a framework for Java development. 
A framework is nothing but a collection of libraries that contains prewritten scripts that trigger set actions. Think of it like an operating system for programming. Frameworks simply help scaffold the process so you don't need to start from scratch every time.

### Understanding Java's Package System

Java's package system enforces a strict relationship between your code's organization and the file system. This isn't arbitrary—it's designed to prevent naming conflicts and make large projects manageable. Here's the key concept:

> **The directory structure MUST match the package declaration.**

If your Java file says `package patient_intake;`, then:
1. The file must be in a directory named `patient_intake/`
2. When compiled, the `.class` file must be in a directory structure that reflects this package


### Common Errors and What They Really Mean

| Error | What's Actually Happening | How to Fix |
|-------|--------------------------|------------|
| `Error: Could not find or load main class` | Java can't find your class at the expected location in the classpath | Check that `-cp` points to the directory **containing** your package folder, not the package folder itself |
| `package your_package does not exist` | The compiler can't find the source files | Make sure your source path is correct, or compile from the correct directory |
| `ClassNotFoundException` | The class exists but isn't on the classpath at runtime | Verify the classpath includes the root directory where your package structure begins |
| `FileNotFoundException` (for resources) | The file path is relative to where you **run** the program, not where the source file is | Use paths relative to your current working directory, or use absolute paths |

### Reading Files: The Path Problem

A common source of confusion is file paths. When your Java code does:
```java
new Scanner(new File("data.csv"))
```

The path `"data.csv"` is resolved from your **current working directory** (where you ran `java` from), NOT from where the `.java` file lives.

**Solutions:**
1. **Use absolute paths** (reliable but not portable):
   ```java
   new File("C:/Users/YourName/Projects/YourProject/src/your_package/data.csv")
   ```
2. **Run from a consistent directory** and use relative paths:
   ```java
   new File("src/main/java/your_package/data.csv")
   ```
3. **Use Java's resource system** (advanced, for packaged applications):
   ```java
   getClass().getResourceAsStream("/your_package/data.csv")
   ```
